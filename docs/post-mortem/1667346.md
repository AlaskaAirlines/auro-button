# AB#1667346

## Executive Summary

Round and square buttons are meant to hold a single icon. Before this work, they often showed up empty when a team used an image or its own graphic. This work makes those buttons show the icon, centered, with any text beside it hidden. A team's own graphic now matches the standard icon size and the button's text color, unless the team chose a color. The button's hidden label now stays hidden even when the icon finishes loading after the button appears.

The same work fixes several related problems:

- Moving keyboard focus to a display-only or link-style button no longer crashes the page's script.
- Clicking a display-only button inside a clickable card no longer pulls focus away from the card's link.
- When a button fails to draw, the real error is now reported instead of being hidden.
- Several documentation examples now follow accessibility guidance and use only public features.

See [AB#1667346](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1667346).

## The Problem

Teams following the button documentation got buttons that looked broken. A round or square button holding an image, or an icon wrapped in another element, rendered empty. A team's own graphic stayed black instead of matching the button, and it ignored the team's icon size setting. Some icons load a moment after the page draws, and in those cases the button's label could stay visible and spill out of the circle.

Separately, code that moved focus to a display-only or link-style button could crash. A display-only button inside a clickable card could take focus away from the card's link. And a button that failed to draw failed silently, hiding the real cause.

Teams copy the documentation examples, and some of those examples were wrong:

- In two examples, the name screen readers announced didn't match the visible label.
- In one example, the label collapsed while a keyboard user was still on the button.
- A count example named the button by its status, not by what it does.
- One example used an internal setting that isn't part of the button's public options.

## Root Cause

- **Icon-only shapes hid anything they didn't recognize as an icon.** In `src/styles/style.scss`, the `symmetrical-styles` mixin visually hid (clipped to 1px) every slotted element in a `circle` or `square` button that wasn't a direct `auro-icon`, `[auro-icon]` or `svg` child. This happened whether or not an icon was present. An `<img>`, or an svg wrapped in a `<span>`, was clipped, so the button rendered empty. The same selector list was also kept by hand in `hasSlottedIcon` in `src/auro-button.js`, so the two lists could drift apart.
- **A slotted svg wasn't sized or colored like `auro-icon`.** Symmetrical shapes sized a slotted svg from hard-coded per-size values in the Sass size map. Slotted `auro-icon` reads `--ds-auro-icon-size` instead, so overriding that token resized `auro-icon` but not the svg. Nothing set the svg's `fill`, so its paths rendered in default black through every color state.
- **The icon-only decision didn't react to icons that upgrade late.** The fix for wrapped icons moved the decision to hide non-icon content into JS, made at render time. A renamed icon (for example, a `<custom-icon>` from `AuroIcon.register`) gets its `auro-icon` attribute only when it upgrades. An attribute change on a slotted child doesn't fire `slotchange`, and the light-DOM `MutationObserver` only watched text inside the `ariaLabel` slots. So if the icon upgraded after the button rendered, the label stayed visible.
- **`focus()` assumed a `<button>`.** `focus()` overrides the public `HTMLElement.focus()` and always called `this.renderRoot.querySelector("button").focus()`. There's no `<button>` to find in three cases, and each one threw a `TypeError`:
  - Static buttons render a `<span>`.
  - Link-mode buttons (`buttonHref`) render an `<a>`.
  - A button that hasn't rendered yet has no inner element.
- **The static `<span>` was focusable.** The template rendered `tabindex="-1"` on the inner `<span>` when `static` was set. That makes a span focusable by script and by mouse click.
- **Layout render errors were swallowed.** `AuroElement.render()` in `src/layoutElement/auroElement.js` caught errors from `renderLayout()` and fell back to `this.getLayout("default")`, which doesn't exist. The fallback threw its own `TypeError` and masked the original error.
- **Documentation examples:**
  - `toggled-text.html` and `right-align.html` had `ariaLabel` slot text ("arrow-up", "in-flight") that didn't match the visible "Text is now shown!" label, which fails WCAG 2.5.3 Label in Name.
  - Their scripts set the shape from whichever event fired last, so `mouseout` collapsed the button while it still had focus.
  - `shape-circle-text.html` labeled count buttons "Quantity 1", which describes a state, not an action.
  - `part_link.html` set the internal `buttonHref` directly on `<auro-button>`.

## The Fix

- **One definition of an icon, including wrapped icons.** `ICON_SELECTOR = "auro-icon, [auro-icon], svg, img"` in `src/auro-button.js`. The `slottedIcons` getter returns the default-slot children that match it or contain a match, so an `<img>` and an svg inside a `<span>` both count as icons.
- **Hiding everything but the icon.** Chrome doesn't support `::slotted(:has(...))`, so CSS alone can't tell a wrapped icon from wrapped text. When the shape is icon-only and an icon is slotted, `.textSlot` gets the `iconOnly` class and `renderIconOnlyStyle()` renders a `<style>` that visually hides every slotted child except the icon children, matched by position (`::slotted(:not(:nth-child(n)))`). The consumer's markup is never modified. The `symmetrical-styles` mixin and its shape loop are removed from `style.scss`.
- **Centering.** `.textSlot.iconOnly` sets `gap: 0`. Hidden bare text is still a zero-width flex item, and the 8px gap beside it pushed the icon 4px off center.
- **svg and img sizing.** `::slotted(svg)` and `::slotted(img)` join the selector list that sets `--ds-auro-icon-size` per size and shape. In `circle` and `square` buttons, a slotted svg or img gets its `width` and `height` from that token, and `object-fit: contain` keeps an img's aspect ratio.
- **svg fill.** In `circle` and `square` buttons, `.textSlot` sets `fill: currentcolor`. `fill` is inherited, so every svg without its own `fill` takes the button text color, slotted directly or wrapped. A consumer's `fill` attribute (for example, `fill="none"` on outline icon sets) beats the inherited value and is kept. `rounded` and `pill` buttons leave a slotted svg's own size and fill alone.
- **Late icons.** `ariaLabelObserver` is renamed `lightDomObserver`. It now also watches `attributeFilter: ["auro-icon"]` and re-renders on any element added or removed inside the light DOM, so a renamed icon that upgrades late, or an icon added inside a wrapper, updates the icon-only state.
- **`focus(options)`.** It returns early when `static` is set, and otherwise calls `this.renderRoot?.querySelector("button, a")?.focus(options)`. The `@private` and `@throws` tags are removed, so `docs/api.md` documents it as public API.
- **Static span.** It gets no `tabindex` at all (`this.static ? undefined : tabindex`).
- **Render errors.** `render()` logs the error and rethrows it, so Lit's update fails and `updateComplete` rejects.
- **Docs:**
  - The default slot and `shape` JSDoc name `<auro-icon>`, `<svg>` and `<img>` as icon options. They tell consumers to set `aria-hidden="true"` on a slotted svg and `alt=""` on a slotted img, and that only a directly slotted icon is sized.
  - The shape docs drop the "text isn't wrapped in an element" limitation. They say which icons count, and that the button can't resize a wrapped icon or recolor an `<img>`.
  - The toggle-text docs explain why the example needs no `ariaLabel` slot. They also explain that a slotted svg changes size and color when the shape changes, and how to avoid it.
- **Examples:**
  - The toggled-text and right-align examples drop the mismatched `ariaLabel` slot. They now track hover and focus separately and show the label while either is active.
  - The count examples use "View cart, 1 item".
  - `part_link.html` and its docs section are removed.
- **Tests:** 28 new tests in `test/auro-button.test.js`:
  - Focus on link-mode, static and unrendered buttons, and a static span that can't take focus.
  - A layout render error that's logged and rethrown.
  - A renamed icon gaining `auro-icon` after render, slotted directly and wrapped.
  - An svg added inside a wrapper after render.
  - svg fill from the button color, slotted directly and wrapped, and a consumer `fill` that's kept.
  - svg size across xs–xl (24/24/24/28/36px), and `<img>` size.
  - svg space kept while loading.
  - A span-wrapped svg, a slotted `<img>`, and wrapped text with no icon.
  - Text hidden beside an `<img>` and beside a wrapped svg.
  - Icon centering, measured from layout: a slotted svg in xs, md and xl circle and square buttons, an `<img>`, a wrapped svg, and an svg with hidden text beside it.

## Why This Works

- **The hide rule and the icon check can't drift apart.** The hide rule is built from the `slottedIcons` result, which comes from `ICON_SELECTOR`. Keeping two hand-written lists in sync is how circle and square buttons ended up rendering empty.
- **Hiding only when an icon is present keeps other content visible.** Without an icon, wrapped count text shows. It's never clipped to nothing.
- **Matching icon children by position avoids touching consumer markup.** The button only reads its children. Frameworks that own the markup never see a foreign attribute, and nothing is left behind when an element moves out of the button.
- **Sizing from `--ds-auro-icon-size` puts svg, img and `auro-icon` on one source of truth.** A token override now resizes all three.
- **Inherited `fill` reaches wrapped svgs and still respects consumer intent.** An inherited value loses to an svg's own `fill` attribute, so outline icon sets that depend on `fill="none"` keep working. `auro-icon` sets its own fill, so it isn't affected.
- **The observer filter stays narrow.** It watches only the `auro-icon` attribute and element changes, which `slotchange` misses. Text edits outside the `ariaLabel` slots don't re-render.
- **`focus()` matches every element the template can render.** `button, a` covers both interactive modes, `static` is intentionally unfocusable, and optional chaining covers the pre-render case. Forwarding `FocusOptions` keeps the override compatible with `HTMLElement.focus()`.
- **Rethrowing makes failures visible.** A rejected `updateComplete` surfaces in tests and in the console. Silently rendering nothing doesn't.
- **Limiting svg size and fill to `circle` and `square` keeps the change in scope.** Applying them in every shape changed existing `rounded` and `pill` buttons, which the ticket doesn't cover (see Iterations That Didn't Work).

## Outcome

- Round and square buttons show a slotted `<auro-icon>`, `<svg>`, `<img>`, or a wrapped icon, centered, instead of rendering empty. Text beside any of them is hidden.
- A team's own svg or img in a round or square button matches the standard icon size and follows the team's icon size setting. An svg takes the button's text color unless the team set its own color, including when it's wrapped.
- The hidden label stays hidden when an icon loads after the button appears, slotted directly or wrapped.
- Moving focus to any button no longer crashes, and display-only buttons never take focus.
- Drawing failures report their real cause.
- The toggled-text, right-align and count examples follow accessibility guidance, and the example that used an internal setting is gone.
- All 75 automated tests pass.
- **Known limitation:** the button can't resize an icon inside a wrapper or recolor an `<img>` (see Ticket Completeness). The docs say to slot the icon directly.
- **Known limitation:** in the "show text on hover" pattern, a team's own svg changes size and color when the button switches between round and pill. The docs recommend `<auro-icon>` for that pattern, or setting the svg's size and color directly.

## Ticket Completeness

9 of 10 requirements resolved and 1 partially resolved. The ticket has no Description or Acceptance Criteria. These requirements come from its Repro Steps ("Desired behavior"), which are cut off partway through step 1.

**Resolved:**

- *Display-only and link-style buttons take focus without errors.* `focus()` targets `button, a`, skips `static`, and is safe before render. Covered by tests.
- *Display-only buttons never take focus.* The static `<span>` has no `tabindex`, and `focus()` does nothing when `static` is set. Covered by tests.
- *A team's own svg follows the team's icon size setting.* The svg is sized from `--ds-auro-icon-size`. Covered by the xs–xl test.
- *A team's own svg uses the button text color unless the team set its own.* `fill: currentcolor` applies only when the svg has no `fill`. Covered by tests.
- *Drawing failures report their real cause.* `render()` rethrows the original error instead of calling the nonexistent `getLayout()`.
- *Documentation examples follow accessibility guidance.* The label-in-name mismatch, the label collapsing while focused, and the status-style count label are fixed.
- *Documentation examples use only public features.* The `buttonHref` link-part example is removed.
- *The label stays hidden no matter when the icon loads.* An `<img>` and a wrapped icon count as icons, so text beside them is hidden. A renamed icon that upgrades late, or an icon added inside a wrapper after render, re-renders the button. Covered by tests.
- *Icons are centered.* Removing the gap in icon-only buttons fixed a 4px offset when bare text sat beside the icon. Centering is covered by layout tests across shapes, sizes and icon types.

**Not resolved / partial:**

- *Round and square buttons always show their icon, in the button's text color and at the standard icon size.* **Partial.** Every icon now shows. A directly slotted `<svg>` or `<img>` is sized, and every svg without its own `fill`, wrapped or not, takes the button color. Two cases can't be covered without the button writing styles into the team's markup, which was ruled out:
  - **A wrapped icon keeps its own size.** `::slotted()` reaches only the top-level element, so the button can't size an svg inside a wrapper. A wrapped `<auro-icon>` sets its own `--ds-auro-icon-size` default, which beats an inherited value.
  - **An `<img>` keeps its own colors.** CSS can't recolor an image's pixels.

## Learnings

- Keep any list of "what counts as X" in one place when both JS and CSS depend on it. Generate the CSS from the JS result, so the two can't drift.
- `::slotted()` takes only a compound selector, and Chrome rejects `:has()` inside it (Firefox and WebKit accept it). To style a slotted element by what it contains, classify it in JS and match it by position, or another selector the component can compute without changing the light DOM.
- Shadow styles can't reach inside a slotted element, but inherited properties can. `fill` and `color` flow into wrapped svgs; `width` and `height` don't.
- Hidden text still takes part in layout. A zero-width flex item still gets a `gap` beside it, so test centering by measuring layout, not by trusting the flex rules.
- `slotchange` doesn't fire for attribute or text changes on an already-slotted element. If rendering depends on a slotted child's attributes, watch them with a `MutationObserver` and a narrow `attributeFilter`.
- Custom elements registered under another tag name get identifying attributes only when they upgrade. Don't assume a render-time query sees the final state.
- Never set `fill: currentcolor` directly on every slotted svg; it overrides the svg's own `fill` attribute. Set it on a shadow container instead, so svgs inherit it. An inherited value loses to a `fill` attribute, so outline icon sets that rely on `fill="none"` keep working, and it reaches wrapped svgs too.
- Overriding a native method like `focus()` makes it public API. Handle every element the template can render, and forward the native options.
- `tabindex="-1"` doesn't make an element unfocusable. It makes a non-focusable element focusable by script and click. To keep an element out of focus entirely, leave `tabindex` off.
- A `catch` in `render()` that returns nothing hides failures: the component renders empty and `updateComplete` still resolves. Log and rethrow.
- Fixing one shape's styling can quietly change other shapes. Before applying a rule to every shape, check that the ticket covers them, and keep a test that guards the other shapes.
- Documentation examples are copied as patterns, so review them against accessibility guidance (label in name, action-based names) like production code.

## Iterations That Didn't Work

- **Sizing and filling a slotted svg in every shape.** In the toggled-text pattern, the svg jumped size and color when hover switched the button between circle and pill. Applying the svg size and fill rules to every shape fixed the jump. But it also changed every `rounded` and `pill` button with a slotted svg, which the ticket doesn't cover:
  - An svg sized by its own `width`/`height` was forced to the icon size.
  - An svg without a `fill` took the button text color instead of black.

  The change was reverted. The rules are limited to `circle` and `square` again, and the docs recommend `<auro-icon>` for the toggled-text pattern.
- **`fill: currentcolor` on every slotted svg.** The first fill rule overrode the svg's own `fill` attribute, so outline icon sets using `fill="none"` (Lucide, Feather, Heroicons outline) rendered as solid shapes. It was narrowed to `svg:not([fill])`, then replaced by an inherited `fill` on `.textSlot`, which also keeps the attribute and reaches wrapped svgs.
- **Removing the `getLayout()` fallback without rethrowing.** Dropping the call to the nonexistent `getLayout()` stopped the `TypeError` from masking the original error. But `render()` then returned `undefined`, so the component rendered nothing and `updateComplete` still resolved. It now rethrows.
- **Counting only direct `auro-icon`, `[auro-icon]` and `svg` children as icons.** An `<img>` or wrapped svg was visible but didn't count as an icon, so text beside it showed. A CSS-only check with `::slotted(:has(svg))` works in Firefox and WebKit but not Chrome. The icon check moved to JS (`slottedIcons`), and the hide rule matches icon children by position.
- **Sizing and coloring a slotted svg with `::slotted(svg)` rules only.** Those rules can't reach an svg inside a wrapper. The fill moved to an inherited rule on `.textSlot`, which reaches wrapped svgs and still loses to a consumer's `fill` attribute.
- **Deciding icon-only at render time alone.** Moving the hide decision into JS so wrapped icons stay visible broke renamed icons that upgrade after the button renders: their labels stayed visible. Extending the light-DOM observer to watch the `auro-icon` attribute fixed it.
