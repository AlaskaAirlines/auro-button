# AB#1642343

## Executive Summary

Circle and square `auro-button`s could not display text. A team building the Food Pre-order experience needed a small circular "add" button that shows a `+` and then changes to a running count ("1", "2", …) each time it's pressed. When they put a number inside a circle button, the button rendered as an empty circle. This work lets circle and square buttons show short text, such as a count, whenever no icon is inside them. Every existing circle and square button that holds an icon looks and behaves exactly as before. See [AB#1642343](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1642343).

## The Problem

A support request showed that `<auro-button>1</auro-button>` displayed "1", but `<auro-button shape="circle">1</auro-button>` displayed an empty circle. The documentation said circle and square shapes "currently only support icon-only buttons", but nothing explained why plain text vanished, and the component already contained a type scale meant for text in those shapes. Teams who needed a numbered circle had no supported way to build one with `auro-button`.

## Root Cause

Two rules in `auro-button` combined to set the text's font size to zero:

- `.contentWrapper` sets `font-size: 0` so inherited text sizing can't affect icon layout. Text gets its size back from a type class (`body-*` / `heading-*`) applied to the inner `.textSlot`.
- `renderLayoutDefault()` applied that type class only when `showText` was true, and `showText` is false for `circle` and `square`.

So a bare text node in a circle or square inherited `font-size: 0` and rendered invisibly. Both rules arrived together in v11.3.4 ("icons should not inherit type styles"). That change also left `getFontSize()`'s `iconOnlyButtonSizeMap`, the heading scale added earlier for text in circle and square buttons, with no effect.

The deliberate hiding for these shapes is separate. The `symmetrical-styles` mixin visually hides slotted *elements* that aren't icons, which the toggled-text pattern relies on. `::slotted()` can't match text nodes, so it never caught bare text.

## The Fix

- **Apply the type class when no icon is slotted.** In `src/auro-button.js`, `.textSlot` now gets its type class when `this.showText || !this.hasSlottedIcon`. The new private `hasSlottedIcon` getter checks for a direct `auro-icon`, `[auro-icon]` or `svg` child. Icon-only shapes therefore pick up the existing heading scale (`heading-xs` to `heading-lg`) only when they hold text instead of an icon.
- **Re-render when the content changes.** The default slot now calls `onDefaultSlotChange()` on `slotchange`, so swapping the icon for a count (or back) updates the class. It follows the same pattern as `onAriaLabelSlotChange()`. Changing the count text itself needs no re-render, because the class doesn't depend on the text's value.
- **No CSS and no new API.** No styles, attributes, properties or events were added or changed.
- **Documentation:** `docs/partials/api.md` now explains that circle and square hold an icon or short bare text, and that a bare number needs an `aria-label` or `ariaLabel` slot. A new "Circle - Text" example uses `apiExamples/shape-circle-text.html`.
- **Tests** in `test/auro-button.test.js` cover:
  - circle and square showing a number
  - the size-to-heading mapping
  - swapping between icon and text in both directions
  - icon plus bare text staying hidden
  - wrapped text plus icon staying visually hidden
  - oblong shapes keeping their `body-*` class

## Why This Works

The only content whose rendering changes is a circle or square that has no icon and contains bare text, which previously rendered as a blank shape that no working usage could depend on. When an icon is present, the class expression reduces to the old `this.showText`, so icon-only buttons, buttons with an icon plus stray text, and the toggled-text pattern render exactly as before. Icon size is set explicitly through `--ds-auro-icon-size` for each shape and size, so the type class can't change icon size. The `slotchange` listener is bound in the Lit template, so Lit manages it, and it keeps working after the element is moved or re-inserted.

## Outcome

Teams can build a numbered circle or square button with `auro-button`, including the Food Pre-order `+` to count pattern, by swapping the button's content. The text uses the type scale the design system already defined for these shapes. Existing circle and square buttons are unchanged.

## Learnings

- A container with `font-size: 0`, whose children get their size back from a class, hides any text that misses the class, and nothing reports an error. When a size-restoring class is gated on a condition, check what happens to content outside that condition.
- `::slotted()` matches elements only, never text nodes. Rules that "hide everything except icons" through `::slotted(:not(...))` leave bare text alone, so bare text behaves differently from wrapped text.
- Binding `@slotchange="${this.requestUpdate}"` passes the event to `requestUpdate()` as a property name. Lit then compares that "property" against `undefined`, finds no change and schedules no update, and only logs a dev-mode warning. Bind a method that calls `this.requestUpdate()` with no arguments.

## Iterations That Didn't Work

- **Applying the type class to icon-only shapes unconditionally** (`[fontSize]: true`) was the first plan. It would have fixed the reported case, but it would also have revealed bare text that is invisible today in circle buttons that contain an icon, such as `<auro-icon></auro-icon> Add`. That is a visible change for existing consumers. Gating on `hasSlottedIcon` keeps those buttons unchanged.
- **Binding `this.requestUpdate` directly as the `slotchange` listener** never re-rendered, for the reason given in Learnings. The swap test caught it, and the listener became a dedicated `onDefaultSlotChange()` method.
